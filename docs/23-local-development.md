# Local Development Guide — Sotto

> **Date**: 2026-02-14
>
> **Summary**: Everything you need to run Sotto on your local machine. Prerequisites, one-command setup, environment variables, what works without API keys, seed data, and troubleshooting.

---

## 1. Prerequisites

| Tool | Version | Why |
|---|---|---|
| **Node.js** | 20+ | Runtime for Next.js + workers |
| **Docker Desktop** | Latest | Runs PostgreSQL 16 + Redis 7 locally |
| **FFmpeg** | 6+ | Audio stitching (segment concatenation + normalization) |
| **Git** | 2.40+ | Version control |

> **Note**: `uv` + `pandoc` are only needed for the pitch pipeline (`scripts/rebuild-pitch.sh`), not day-to-day development.

---

## 2. Quick Start

```bash
npm run setup   # installs deps, starts Docker, generates .env.local, pushes DB schema
npm run dev     # starts web (Next.js) + workers (BullMQ) concurrently
```

Open [http://localhost:3000](http://localhost:3000).

### What `npm run setup` does

The setup script (`scripts/setup.sh`) runs these steps in order:

1. Installs system dependencies via `scripts/install-deps.sh`
2. `npm install` — installs Node.js packages
3. `uv sync --group pitch` — installs Python deps for pitch pipeline
4. `docker-compose up -d` — starts PostgreSQL + Redis containers
5. Generates `.env.local` with auto-configured `DATABASE_URL`, `REDIS_URL`, `NEXTAUTH_SECRET`, `NEXTAUTH_URL`
6. `npx prisma db push` — pushes schema to the local database
7. `npx prisma generate` — generates the Prisma client

## 3. Manual Setup

If you prefer step-by-step control:

```bash
# 1. Install Node.js dependencies
npm install

# 2. Start PostgreSQL + Redis
docker-compose up -d

# 3. Create .env.local (copy from example, then edit)
cp .env.example .env.local
# Edit .env.local — see Section 5 for recommended values

# 4. Push database schema
npx prisma db push

# 5. Generate Prisma client
npx prisma generate

# 6. Start development
npm run dev
```

## 4. Environment Variables

The canonical reference is `.env.example` — it documents every variable with `[AUTO]`, `[REQUIRED]`, and `[OPTIONAL]` tags.

### Impact Table

| Variable(s) | Required? | What breaks without it |
|---|---|---|
| `DATABASE_URL` | Yes (auto) | Everything — app won't start |
| `REDIS_URL` | Yes (auto) | Workers, job queue, caching |
| `NEXTAUTH_SECRET` + `NEXTAUTH_URL` | Yes (auto) | Auth — sessions won't work |
| OAuth provider (Google or GitHub) | Yes | Login — no buttons render without at least one provider configured |
| `ANTHROPIC_API_KEY` | For AI features | Discovery chat, script generation, Q&A |
| TTS key (`ELEVENLABS_API_KEY` or `OPENAI_API_KEY`) | For audio | Audio generation pipeline |
| `R2_*` / `AWS_*` | No | Set `STORAGE_PROVIDER=local` instead |
| `STRIPE_*` | No | Voice marketplace only (Stripe Connect for voice payments) — set `PAYMENT_PROVIDER=none` for local dev |
| `TWITTER_*` | No | Only needed for @sottofm tweet-to-podcast bot |
| `TELEGRAM_BOT_TOKEN` | No | Only needed for Telegram dev notifications (`@SottoFMDevBot`) |
| `VAPID_*` | No | Web push notifications won't send |

Items marked **(auto)** are handled by `npm run setup`.

## 5. Recommended `.env.local` for Local Dev

```env
# ── Auto-generated by npm run setup ──
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/sotto?schema=public"
REDIS_URL="redis://localhost:6379"
NEXTAUTH_SECRET="<auto-generated-by-setup>"
NEXTAUTH_URL="http://localhost:3000"

# ── Auth — add at least one (GitHub is easiest) ──
GITHUB_CLIENT_ID=...
GITHUB_CLIENT_SECRET=...
# Callback URL: http://localhost:3000/api/auth/callback/github

# ── AI — pick one ──
ANTHROPIC_API_KEY=sk-ant-...
# Or: AI_PROVIDER=openai + OPENAI_API_KEY=sk-...
# Or: AI_PROVIDER=claude-code (uses local Claude CLI)

# ── TTS — pick one (optional, only for audio generation) ──
ELEVENLABS_API_KEY=...
# Or: OPENAI_API_KEY=sk-... (OpenAI TTS, cheaper)

# ── Local overrides — no cloud accounts needed ──
STORAGE_PROVIDER=local
PAYMENT_PROVIDER=none
```

## 6. What Works Without API Keys

Progressive disclosure — which features unlock at each tier:

| Keys configured | What works |
|---|---|
| **Zero keys** | Landing page, feed, pricing page, public podcast pages (if seeded) |
| **+ OAuth** (GitHub or Google) | Login, dashboard, settings, profiles, follow/unfollow |
| **+ AI key** (Anthropic or OpenAI) | Discovery chat, script generation, Q&A interactions |
| **+ TTS key** (ElevenLabs or OpenAI) | Full audio generation pipeline, end-to-end podcast creation |

## 9. Docker

### Local development (`docker-compose.yml`)

Runs PostgreSQL 16 (pgvector) + Redis 7 only. The app itself runs on bare metal via `npm run dev`.

```bash
# Start services
docker-compose up -d

# Stop services (keeps data)
docker-compose down

# Stop + delete all data (fresh start)
docker-compose down -v

# View logs
docker-compose logs -f postgres
docker-compose logs -f redis
```

### Production (`docker-compose.prod.yml`)

Used for Hetzner VPS deployment. **Do NOT use locally** — it runs the full app stack in containers with production configuration.

## 10. Troubleshooting

### Port 5432 or 6379 already in use

Another PostgreSQL or Redis instance is running. Either stop it or change the port mapping in `docker-compose.yml`:

```bash
# Check what's using the port
lsof -i :5432
lsof -i :6379

# Kill existing process, or change docker-compose.yml ports:
#   - '5433:5432'  → then update DATABASE_URL port to 5433
```

### Login page shows no buttons

No OAuth provider is configured. Add at least one to `.env.local`:
- **GitHub** (easiest): Create an OAuth app at [github.com/settings/developers](https://github.com/settings/developers) with callback URL `http://localhost:3000/api/auth/callback/github`
- **Google**: Create credentials at [console.cloud.google.com](https://console.cloud.google.com/apis/credentials) with redirect URI `http://localhost:3000/api/auth/callback/google`

### `prisma generate` fails after schema change

Run `npx prisma db push` first to sync the schema to the database, then `npx prisma generate`.

### FFmpeg not found

Install via your package manager:

```bash
# macOS
brew install ffmpeg

# Ubuntu/Debian
sudo apt install ffmpeg
```

### Workers crash on startup

Redis is likely not running. Check with:

```bash
docker-compose ps          # should show sotto-redis as "running"
redis-cli ping             # should return PONG
```

If Redis is down: `docker-compose up -d redis`

### `STORAGE_PROVIDER=local` — caveat

Some workers import `r2.ts` directly and may fail without R2 credentials. If you hit this, either:
- Set R2 credentials (even a test bucket works)
- Or skip audio features and focus on web/chat development
